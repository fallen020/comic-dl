Download a build from the [GitHub Releases page](https://github.com/fallen020/comic-dl/releases). It runs on its own — no Python, no Node. <VersionBadge /> is the version these filenames use.

Building from source is the fallback, and the only option on macOS. It needs Python 3.11+ and [uv](https://docs.astral.sh/uv/getting-started/installation/).

<Warning title="pip does not work">

`pip install comic-dl` fails: the name on PyPI belongs to an unrelated project. Use a release binary or build from source.

</Warning>

## Check your architecture

Filenames encode the CPU, so find yours first:

<Tabs idPrefix="arch" label="Architecture check" tabs={[{ label: 'Windows', value: 'win' }, { label: 'Linux / macOS', value: 'unix' }]}>

<div data-panel="win" role="tabpanel" id="panel-arch-win" aria-labelledby="arch-win">

```powershell
$ echo $env:PROCESSOR_ARCHITECTURE   # prints AMD64 or ARM64
```

</div>

<div data-panel="unix" role="tabpanel" id="panel-arch-unix" aria-labelledby="arch-unix">

```bash
$ uname -m
```

</div>

</Tabs>

Two answers, and every comic-dl filename is built from one of them:

| What you got | Your CPU | Debian uses | Fedora / Arch use |
| :----------- | :------- | :--------- | :---------------- |
| `x86_64`, `AMD64` | Intel / AMD | `amd64` | `x86_64` |
| `aarch64`, `ARM64` | Apple Silicon, Snapdragon, Raspberry Pi | `arm64` | `aarch64` |

Same chips, different spellings.

## Which file do I need?

Pick your OS:

<Tabs idPrefix="file" label="Download file" tabs={[{ label: 'Windows', value: 'windows' }, { label: 'Debian / Ubuntu', value: 'debian' }, { label: 'Fedora', value: 'fedora' }, { label: 'Arch Linux', value: 'arch' }, { label: 'macOS', value: 'macos' }, { label: 'Android', value: 'android' }]}>

<div data-panel="windows" role="tabpanel" id="panel-file-windows" aria-labelledby="file-windows">

```text
comic-dl-0.0.5-windows-amd64.zip     or the bare comic-dl-0.0.5-windows-amd64.exe
```

x86-64 only. No native ARM64 build — the amd64 one runs emulated.

</div>

<div data-panel="debian" role="tabpanel" id="panel-file-debian" aria-labelledby="file-debian">

```text
comic-dl_0.0.5_amd64.deb             x86-64
comic-dl_0.0.5_arm64.deb             ARM64
```

</div>

<div data-panel="fedora" role="tabpanel" id="panel-file-fedora" aria-labelledby="file-fedora">

```text
comic-dl-0.0.5-1.fc44.x86_64.rpm     x86-64
comic-dl-0.0.5-1.fc44.aarch64.rpm    ARM64
```

Keep the `-1.fc44.` build marker exactly as written. RHEL compatibility is not guaranteed.

</div>

<div data-panel="arch" role="tabpanel" id="panel-file-arch" aria-labelledby="file-arch">

```text
fallen020-comic-dl-0.0.5-1-x86_64.pkg.tar.zst  x86-64
```

No ARM64 package — build from source there.

</div>

<div data-panel="macos" role="tabpanel" id="panel-file-macos" aria-labelledby="file-macos">

Nothing to download. macOS builds are unsigned and unnotarized, so no binary is published. Build from source — the solver uses the built-in WKWebView and needs nothing extra.

</div>

<div data-panel="android" role="tabpanel" id="panel-file-android" aria-labelledby="file-android">

Not supported. It may run under [Termux](https://termux.dev) from source, but the webview solver has not been validated there. Build the `.cbz` files on a desktop and copy them across.

</div>

</Tabs>

Only the version number changes between releases. Artifacts are tested in CI before publication — if one fails to install or run, report it with the release version and operating system.

## Install by platform

With the file downloaded, install it:

<Tabs idPrefix="install" label="Install method" tabs={[{ label: 'Windows', value: 'windows' }, { label: 'Debian / Ubuntu', value: 'debian' }, { label: 'Fedora', value: 'fedora' }, { label: 'Arch Linux', value: 'arch' }, { label: 'From source', value: 'source' }]}>

<div data-panel="windows" role="tabpanel" id="panel-install-windows" aria-labelledby="install-windows">

Unzip it and run `comic-dl.exe` from a terminal:

```powershell
$ .\comic-dl.exe self version
```

Use **Windows Terminal** — the CLI output uses Unicode glyphs. In classic `cmd.exe`, run `chcp 65001` first.

- **Windows on ARM64:** there is no native build; the amd64 binary runs emulated. Build from source for native speed.
- The webview solver needs the Microsoft Edge WebView2 Runtime. It ships with current Windows versions; if the solver fails to start, install it from Microsoft separately.

</div>

<div data-panel="debian" role="tabpanel" id="panel-install-debian" aria-labelledby="install-debian">

```bash
$ sudo apt install ./comic-dl_0.0.5_amd64.deb
```

On ARM64, install the `_arm64.deb` file instead.

</div>

<div data-panel="fedora" role="tabpanel" id="panel-install-fedora" aria-labelledby="install-fedora">

```bash
$ sudo dnf install ./comic-dl-0.0.5-1.fc44.x86_64.rpm
```

Use the exact filename, including the Fedora build marker (`-1.fc44.`), and substitute `.aarch64` for `.x86_64` on ARM64. RHEL compatibility is not guaranteed — if dependency resolution fails, build from source.

</div>

<div data-panel="arch" role="tabpanel" id="panel-install-arch" aria-labelledby="install-arch">

```bash
$ sudo pacman -U fallen020-comic-dl-0.0.5-1-x86_64.pkg.tar.zst
```

No ARM64 Arch package is provided; on ARM64, build from source.

<Warning title="The AUR package is a different project">

The AUR hosts an unrelated package also named `comic-dl`. Installing it with `yay` or `paru` swaps this program out for that one. Get the `fallen020-comic-dl-*.pkg.tar.zst` file from the release page instead; no AUR entry exists under that name, so helpers never touch it.

</Warning>

If you installed the old `comic-dl` package (0.0.4 or earlier), switch to the new name:

```bash
$ sudo pacman -Rns comic-dl   # remove the old package name
$ sudo pacman -U fallen020-comic-dl-0.0.5-1-x86_64.pkg.tar.zst
```

Your config, cookies, and library database are untouched.

</div>

<div data-panel="source" role="tabpanel" id="panel-install-source" aria-labelledby="install-source">

Needs Python 3.11+ and `uv` on your `PATH`:

```bash
$ python3 --version
$ uv --version
```

```bash
$ git clone https://github.com/fallen020/comic-dl
$ cd comic-dl
$ uv sync
```

`uv sync` creates `.venv/` and installs the project with its dependencies. Run it with `uv run` — the same command works everywhere, Windows PowerShell included:

```bash
$ uv run comic-dl self version
```

For the development environment, with test and lint tooling, use `uv sync --extra dev --locked` instead.

- **macOS:** no binary is published, so build from source. The solver uses the built-in WKWebView; nothing extra to install.
- **Android:** not supported. It may run under [Termux](https://termux.dev) from source, but this is untested and the webview solver has not been validated there. Build the `.cbz` files on a desktop and copy them across.

</div>

</Tabs>

## Webview solver libraries (Linux)

The Cloudflare challenge solver ships with the application, and the Debian, Fedora, and Arch packages declare its GTK and WebKit dependencies — installing comic-dl pulls the whole stack in.

A source checkout needs those libraries separately, because the pywebview wheel cannot ship them:

<Tabs idPrefix="pkg" label="System packages" tabs={[{ label: 'Debian / Ubuntu', value: 'debian' }, { label: 'Fedora', value: 'fedora' }, { label: 'Arch Linux', value: 'arch' }]}>

<div data-panel="debian" role="tabpanel" id="panel-pkg-debian" aria-labelledby="pkg-debian">

```bash
$ sudo apt install python3-gi python3-gi-cairo gir1.2-webkit2-4.1
```

</div>

<div data-panel="fedora" role="tabpanel" id="panel-pkg-fedora" aria-labelledby="pkg-fedora">

```bash
$ sudo dnf install python3-gobject webkit2gtk4.1
```

</div>

<div data-panel="arch" role="tabpanel" id="panel-pkg-arch" aria-labelledby="pkg-arch">

```bash
$ sudo pacman -S python-gobject webkit2gtk-4.1
```

</div>

</Tabs>

On headless Linux, run under `xvfb-run` or pass `--solver impersonation` to skip the webview entirely.

## Verify

Check that it runs before your first download:

```bash
$ comic-dl self version          # binary install
$ uv run comic-dl self version   # source checkout
```

### Checksums

Every release attaches a `SHA256SUMS` file. After downloading the package, fetch it from the same release and check the download against it:

```bash
$ curl -LO https://github.com/fallen020/comic-dl/releases/download/v0.0.5/SHA256SUMS
$ sha256sum -c SHA256SUMS --ignore-missing
```

`OK` means the file matches the published checksum; `--ignore-missing` skips the release files you did not download.

## Shell completions

Completions exist for bash, zsh, fish, and PowerShell. Binary installs put `comic-dl` on `PATH`; from a source checkout, prefix with `uv run`:

<Tabs idPrefix="sh" label="Shell" tabs={[{ label: 'bash', value: 'bash' }, { label: 'zsh', value: 'zsh' }, { label: 'fish', value: 'fish' }, { label: 'PowerShell', value: 'powershell' }]}>

<div data-panel="bash" role="tabpanel" id="panel-sh-bash" aria-labelledby="sh-bash">

```bash

$ source <(comic-dl completion bash)
```

```bash
# source checkout
$ source <(uv run comic-dl completion bash)
```

</div>

<div data-panel="zsh" role="tabpanel" id="panel-sh-zsh" aria-labelledby="sh-zsh">

```bash
# binary install
$ eval "$(comic-dl completion zsh)"
```

```bash
# source checkout
$ eval "$(uv run comic-dl completion zsh)"
```

</div>

<div data-panel="fish" role="tabpanel" id="panel-sh-fish" aria-labelledby="sh-fish">

```bash

$ comic-dl completion fish | source
```

```bash
# source checkout
$ uv run comic-dl completion fish | source
```

</div>

<div data-panel="powershell" role="tabpanel" id="panel-sh-powershell" aria-labelledby="sh-powershell">

## Update

`comic-dl self update` works out how comic-dl was installed and updates it through whichever tool owns that install. It never downgrades, and nothing changes until you confirm:

```bash
$ comic-dl self update
```

- `--check` reports the installed and latest versions and changes nothing.
- `-y` / `--yes` skips the confirmation. Without a TTY and without `--yes`, it refuses rather than running unattended.
- `--channel beta` opts into pre-releases.

What it does depends on the install:

<Tabs idPrefix="upd" label="Update by install type" tabs={[{ label: 'Windows', value: 'windows' }, { label: 'Debian / Ubuntu', value: 'debian' }, { label: 'Fedora', value: 'fedora' }, { label: 'Arch Linux', value: 'arch' }, { label: 'uv tool', value: 'uv' }, { label: 'From source', value: 'source' }]}>

<div data-panel="windows" role="tabpanel" id="panel-upd-windows" aria-labelledby="upd-windows">

Prints the Releases page. The standalone executable does not replace itself yet.

</div>

<div data-panel="debian" role="tabpanel" id="panel-upd-debian" aria-labelledby="upd-debian">

Downloads the `.deb` for your architecture, then runs `sudo apt install --yes` on it.

</div>

<div data-panel="fedora" role="tabpanel" id="panel-upd-fedora" aria-labelledby="upd-fedora">

Downloads the `.rpm`, then runs `sudo dnf install --yes` on it.

</div>

<div data-panel="arch" role="tabpanel" id="panel-upd-arch" aria-labelledby="upd-arch">

Downloads the `.pkg.tar.zst`, then runs `sudo pacman -U --noconfirm` on it.

</div>

<div data-panel="uv" role="tabpanel" id="panel-upd-uv" aria-labelledby="upd-uv">

Runs `uv tool upgrade comic-dl`.

</div>

<div data-panel="source" role="tabpanel" id="panel-upd-source" aria-labelledby="upd-source">

Prints `git pull` and `uv sync`. It never modifies your checkout.

</div>

</Tabs>

### Can I just install the newer package over the old one?

Yes — on Linux that is what `self update` does anyway, since package managers upgrade in place. If you already downloaded the newer file, install it the same way you installed the first one:

<Tabs idPrefix="man" label="Manual upgrade" tabs={[{ label: 'Debian / Ubuntu', value: 'debian' }, { label: 'Fedora', value: 'fedora' }, { label: 'Arch Linux', value: 'arch' }]}>

<div data-panel="debian" role="tabpanel" id="panel-man-debian" aria-labelledby="man-debian">

```bash
$ sudo apt install ./comic-dl_0.0.5_amd64.deb
```

</div>

<div data-panel="fedora" role="tabpanel" id="panel-man-fedora" aria-labelledby="man-fedora">

```bash
$ sudo dnf install ./comic-dl-0.0.5-1.fc44.x86_64.rpm
```

</div>

<div data-panel="arch" role="tabpanel" id="panel-man-arch" aria-labelledby="man-arch">

```bash
$ sudo pacman -U fallen020-comic-dl-0.0.5-1-x86_64.pkg.tar.zst
```

</div>

</Tabs>

Swap in the version you downloaded. No uninstall first — the package manager upgrades over the existing install, and your config, cookies, and library database are left alone.

[Version and Updates](../usage/self-update/) covers this in more detail.

## Uninstall

Two steps, and only the first removes the program. **Your downloads are never touched.**

### 1. Remove the program

<Tabs idPrefix="un" label="Uninstall" tabs={[{ label: 'Windows', value: 'windows' }, { label: 'Debian / Ubuntu', value: 'debian' }, { label: 'Fedora', value: 'fedora' }, { label: 'Arch Linux', value: 'arch' }, { label: 'From source', value: 'source' }]}>

<div data-panel="windows" role="tabpanel" id="panel-un-windows" aria-labelledby="un-windows">

Delete the folder you unzipped comic-dl into.

</div>

<div data-panel="debian" role="tabpanel" id="panel-un-debian" aria-labelledby="un-debian">

```bash
$ sudo apt remove comic-dl
```

</div>

<div data-panel="fedora" role="tabpanel" id="panel-un-fedora" aria-labelledby="un-fedora">

```bash
$ sudo dnf remove comic-dl
```

</div>

<div data-panel="arch" role="tabpanel" id="panel-un-arch" aria-labelledby="un-arch">

```bash
$ sudo pacman -Rns fallen020-comic-dl
```

</div>

<div data-panel="source" role="tabpanel" id="panel-un-source" aria-labelledby="un-source">

```bash
$ rm -rf comic-dl
```

</div>

</Tabs>

### 2. Optionally remove the data

Skip this if you plan to reinstall — keeping the directories means `comic-dl library list` still knows your series when you come back. comic-dl is already gone at this point, so this is plain file removal. Each platform's commands remove the config, the cookie jar, the scrape cache, and the library database.

<Tabs idPrefix="data" label="Data paths" tabs={[{ label: 'Windows', value: 'windows' }, { label: 'Linux', value: 'linux' }, { label: 'macOS', value: 'macos' }]}>

<div data-panel="windows" role="tabpanel" id="panel-data-windows" aria-labelledby="data-windows">

```powershell
> rmdir /s /q "%LOCALAPPDATA%\comic-dl"
```

Config, cookies, cache, and `library.db` all live under `%LOCALAPPDATA%\comic-dl` on Windows.

</div>

<div data-panel="linux" role="tabpanel" id="panel-data-linux" aria-labelledby="data-linux">

```bash
$ rm -rf ~/.config/comic-dl         # config.toml + cookies.db
$ rm -rf ~/.cache/comic-dl          # scrape cache
$ rm -rf ~/.local/share/comic-dl    # library.db
```

</div>

<div data-panel="macos" role="tabpanel" id="panel-data-macos" aria-labelledby="data-macos">

```bash
$ rm -rf ~/Library/Application\ Support/comic-dl   # config.toml + cookies.db + library.db
$ rm -rf ~/Library/Caches/comic-dl                 # scrape cache
```

</div>

</Tabs>

Your downloaded `.cbz` archives live wherever you told comic-dl to put them — nothing here removes those.

To clear just the cookies and cache without deleting anything, run `comic-dl cookie clear` and `comic-dl cache clear` *before* removing the program. Exact paths, including the `$COMIC_DL_CONFIG` and `$COMIC_DL_DATA_DIR` overrides: [Privacy](../privacy/).
